# Modular Character Sheet — Documentation

An offline HTML character sheet for **D&D 5e (2014 rules)**, built for optimized play. The page (`character-sheet.html`) loads its logic from small modules in `src/`. **Serve the folder** rather than opening the file directly — there's a ready `static` config in `.claude/launch.json` (`python3 -m http.server`) — this is required for the spell/equipment libraries to auto-load (see below); browsers block `fetch()` of local files opened via `file://`. No install, no accounts; game data is user-supplied (see below).

> **Status:** prototype (v0.12). Cosmetics/theming exist (8 selectable themes) but the layout itself is still "function over form."

## Where game data comes from
The sheet draws a line between two kinds of game data:

- **Small, fixed facts get hardcoded — mechanics only, never prose.** Things like each class's hit die and casting type (`CLASS_DATA`/`SUBCLASS_CASTING` in [data.js](src/data.js), which includes non-SRD facts like Eldritch Knight/Arcane Trickster's third-caster progression), the multiclass spellcaster slot table (`MULTICLASS_SLOTS` in [derived.js](src/derived.js)), the default magic-item prices by rarity (`RARITY_DEFAULT_GP` in [item-library.js](src/item-library.js), averaged from XGE's Magic Item Price table), and the [feature effects database](#feature-effects-automatic-mechanics) (`effects/`) are short, contain no descriptive text lifted from any sourcebook, and drive the auto-calculated fields (selectable as "auto", with an explicit override always available). The effects database in particular is inert overlay, not content — an entry only ever does anything if your own imported `data/` happens to contain a feature with a matching name.
- **Bulk or descriptive content is user-supplied.** Anything that's a lot of data (the full spell list, the equipment list, every class/race/feat's actual description text) is never bundled — you supply it yourself by dropping 5e.tools' own `data/` directory next to `character-sheet.html` (see [Spell library](#spell-library-5etools-import) / [Features](#features-5etools-import-race--class--feats) / [Equipment library](#equipment-library-5etools-import)). This is also why `data/` is gitignored rather than committed.

When adding a new auto-calculated feature, ask which bucket it falls into: a short, fixed, prose-free table → hardcode it with an override box (see Max HP and Spell Slots below, or the effects database); anything bigger, descriptive, or that reproduces sourcebook text → make it an import, not a bundled dataset.

## Characters (tabs, creation, levelling up)
One sheet holds **several characters**, each on its own tab in the strip above the modules. The tab shows the character's name and total level; clicking another tab switches to it, clicking the **active** tab renames it, and **×** deletes it (with a confirmation — and never the last one, so you're never left with no character at all). Switching commits whatever is on screen first, so an in-progress edit isn't lost by clicking away from it.

Storage is one `charsheet-roster` key holding every character, replacing the old single `charsheet-v0` slot. **If you had a character before this existed, it is migrated in as your first tab automatically** — and `charsheet-v0` is *deliberately left on disk untouched* rather than deleted, so the pre-roster copy is still there to recover by hand if anything about the migration went wrong. Migration only runs when no roster exists at all, so it can't resurrect a stale copy later. Export/Import still work on **one character at a time** — the character you're looking at.

### Creating a character
**+ New character** opens a five-step wizard that follows PHB'14 chapter 1 ("Step-by-Step Characters", p11–15) in the book's own order, because that's the order the choices depend on each other in — your race sets ability increases you can't apply until scores exist, and your class sets the hit die you can't compute HP from until you know CON. The five steps are **tabs**: Back/Next walk them in order, but any step can be clicked at any time, so you can go back and change your race after seeing what it did to your scores. A step with something still wrong is marked, and **Create** stays disabled — with the reason — until every step is satisfied, wherever you happen to be standing.

1. **Choose a Race** (p11) — race and subrace. The step shows the **ability increases** the choice grants; any that are "*and two others of your choice*" (Half-Elf, Variant Human, Custom Lineage) get their own dropdowns, and step 1 won't pass until they're picked. A subrace called **(base)** is the race's default version, the one with no subrace of its own — for a PHB Human that's the +1-to-everything build, as against Variant. Races whose **size** is left to the player (Dhampir and the other "Small or Medium" races) get a size picker. The race's **traits** are listed, with the ones that involve a choice you make yourself — Simic Hybrid's Animal Enhancement, a Variant Human's feat — marked ✎; the sheet doesn't guess those, and the full text is in the Features module once the character exists.
2. **Choose a Class** (p11) — a small class table rather than a single class, so a character can **start multiclassed**: each row has class, subclass and **level, defaulting to 1** but editable, with the 20-level cap applied to the *total*. Starting a character mid-campaign, at any level or split, takes no level-up dialogs. **Multiclassing ability prerequisites (PHB p163) are checked** against your step-3 scores, for every class in the mix rather than just the newest, and block the step until they're met. A class whose data doesn't state a prerequisite isn't failed for it.
3. **Determine Ability Scores** (p12–13) — **standard array** (15/14/13/12/10/8), **point buy** (the PHB's cost table and 27-point budget, with the remaining budget shown live and the step blocked while you're over it), **roll 4d6 drop lowest** (logged to the Event Log, like every other roll on the sheet), or **enter manually**. Racial increases are applied on top and shown as a running final score — and the choosable ones appear here too, as **the same control as step 1**, so changing it in either place changes it in both.
4. **Describe Your Character** (p13) — name and background. Backgrounds are mechanically relevant, so this is a real pick: choosing one applies its stated skill proficiencies to the Skills module and its stated tools and languages to Proficiencies. Anything the data leaves as a *choice* ("any one artisan's tool", "two standard languages") is shown but **not** picked for you. Ticking **custom background** gives you PHB p125 instead: any two skills, any two tool proficiencies or languages, and one feature borrowed from any background. A background's **choose N of…** proficiency blocks are pickers rather than a sentence: the data's own options, one dropdown per slot, and what you pick lands on the built character.
5. **Choose Equipment** (p14) — take your class's **equipment package** or its **starting gold**. The package is the book's own (a)/(b) choices, one row each, and the items you pick are added to Inventory by name. Gold is either rolled from the class's own dice (5d4 × 10 for a Fighter) and logged, or you can **take the average** (125 gp for that Fighter) — the same "take the fixed value instead of rolling" choice the rules already give for hit points, applied to the one other roll character creation asks for. Where the data says "any martial weapon" rather than naming an item there's nothing to add automatically, so those are counted and reported for you to pick from the Equipment Library. **Starting at Higher Level** (DMG p38) is here too: tick it, pick the campaign's magic level, and the extra starting gold for your level band is rolled and added — the magic items that table also grants are *reported* rather than granted, since the sheet has no random magic-item table and inventing one would be worse than telling you what you're owed.

The character it produces is written through the same `collectState()` shape as a hand-built one, so there's no "made by the wizard" flavour of character to maintain. Current HP starts at max.

Race, subrace, class, subclass and background are **comboboxes** ([src/combobox.js](src/combobox.js)): a text box with a **▾ arrow** that drops the whole list, and typing filters that list live as you go (prefix matches first, so "elf" offers Elf before Half-Elf). ↑/↓ move through the matches and Enter picks one. Free text is still accepted on purpose — the libraries are user-supplied and may be absent entirely (see [Where game data comes from](#where-game-data-comes-from)), so a race the sheet has never heard of stays typeable and the list is a convenience, never a gate.

Each of race, class and background also has a **Books** filter above it, in the same spirit as the Spell and Equipment libraries' own Source filters: switch off the books your table doesn't use and their entries disappear from the picker. Whatever you've already chosen always survives the filter, so hiding a book can't silently blank a choice. **Cancel** sits alone at the bottom left, away from Back/Next/Create: it's the one button that throws the whole character away.

**Racial ability increases** come from 5e.tools' own `ability` blocks, with two things that aren't obvious from the data. A `choose` block carries an **amount** — "+1 to two of these" and "+2 to one of these" are both `choose`, and treating the second as +1 halves it (Custom Lineage). And a subrace's block sometimes *adds* to the race's and sometimes *replaces* it, with nothing in the data saying which: a Mountain Dwarf's STR +2 adds to Dwarf's CON +2 (a legal +4 total), while a Draconblood Dragonborn's INT +2/CHA +1 is that subrace's whole increase, not an extra +3 on top of the base Dragonborn's. The rule used: **a subrace block that is already a complete racial increase — totalling 3 or more, or containing a `choose` — replaces; anything smaller adds.** That is right for every PHB and EGW case; where it isn't, the numbers are on screen in step 1 rather than silently baked in. Some races (mostly Monsters of the Multiverse reprints) carry no `ability` at all, because their increase is the floating "+2 and +1 to any" rule — those come through as nothing, which the step says rather than pretending otherwise.

**Customizing Your Origin** (TCE p8) is a tick-box next to the increases. With it on, the race's *fixed* increases become free picks that keep their sizes — a Mountain Dwarf's CON +2 / STR +2 becomes two +2s you assign wherever you like — and no two may land on the same ability, so the pickers grey out a score already taken. Increases the race already left to choice are unaffected; they were free to begin with. The total never changes: reassigning is not a buff.

*One step is deliberately thin.* Step 4 collects name and background only — personality traits, ideals, bonds, flaws and backstory are on this document's **Not planned** list, so the wizard doesn't ask for fields the sheet has nowhere to put. Background data comes from **`data/backgrounds.json`**, loaded alongside races and classes; without that file a background is still recorded, just not looked up.

### Levelling up
**Level** sits next to **XP** in the Character module, and the two are two views of one number (PHB p15's Character Advancement table). Type a level and XP jumps to that level's threshold; type XP and the level follows. A running "**1,300 XP to level 6**" says what you still owe, and the Level box highlights once your XP has already earned the next level.

The Level box is not a third place your level is stored — your actual level is the sum of the Classes table, as it always has been, and everything derived reads it from there. The box is a *request*:

- **Raising it opens the Level Up dialog**, so the new level lands in a specific class with hit points chosen rather than appearing from nowhere. (This replaces the old standalone Level Up button.)
- **Lowering it asks first**, then takes the levels off the bottom of the Classes table, resets XP to that level's threshold, and clears any Max HP override — an override written for a level that no longer exists would silently inflate the character. Levelling down doesn't try to guess *which* class should lose the level: it takes from the last row that has one to give, says so, and leaves the rest to you.

Crossing an XP threshold never takes the level on its own. Gaining a level is a decision (PHB p15), so the sheet offers it and waits.

In the Level Up dialog you pick which class gains the level — or **multiclass into a new one at level 1** — and it previews the features you'll gain at that level, read from the same data the Features panel renders from, so what it promises is exactly what shows up. **Multiclassing prerequisites (PHB p163)** are checked here against the live sheet and reported for every class in the mix; they're reported rather than enforced, since the scores may be about to change.

For hit points you either **take the fixed average** or **roll the Hit Die** (PHB p15). Taking the average writes nothing: Max HP is computed from your classes and CON and *already* assumes the average, so the number simply moves on its own. A **rolled** result has nowhere else to live, so the difference between your roll and the average is folded into the **Max HP override** box — and once that box is in use it shadows the formula entirely, so every later level-up adds its hit points there too (including whatever per-level bonuses the formula itself would have applied, e.g. a Hill Dwarf's Dwarven Toughness). Current HP rises with the maximum.

### Groups and the shared Event Log
Character tabs can be **dragged to reorder**, and **dropped onto each other to form a group** — the middle of a tab means "group these", the edges mean "put it here", and both are shown while you drag. A group is boxed on the tab bar, and **where a tab lands is what decides its group**: drop it inside a box and it is in that group, drop it outside every box and it is in none. Dragging a tab out is how you leave a group — there is no button for it, and the box outlines itself in red while a drag is about to take a member out of it. **Anywhere off the tab bar counts as out**, so dragging a tab downwards into the sheet works as well as dragging it sideways past the box; on the bar you are rearranging or regrouping, anywhere else you are leaving.

Characters in a group **share one Event Log**. The case this is for is a character and the things they command — a wizard and their familiar, a druid and a summon, a party one person is running — where what matters is that everything happened in *one order*: roll on the familiar's sheet and it lands in the same stream as the wizard's attack, because that's how the turn actually went. Merging two logs interleaves them by timestamp rather than stacking one on the other, and a character leaving a group takes a copy of the shared history rather than losing it — as does the one left behind when a group drops to a single member and dissolves. A drag moves **one tab**, never the whole group: that is what makes dragging a tab out of the box able to remove that tab and only that tab. A tab dragged off the bar keeps its place in the order, except that the group it left is closed up behind it, so leaving from the middle of a group never splits it into two boxes.

Ungrouped characters each keep their own log, and it now survives a reload and a character switch (it used to be a single page-wide panel that reset on refresh). Logs are capped at 300 entries each so storage can't run away.

Both the creator and Level Up record what they did in the [Event Log](#event-log-and-the-dice-roller).

## Number boxes (math input)
Any bounded number box (ability scores, class level, current/temp HP, AC, speed, spell slots used) accepts arithmetic:

| You type | Result (box was `30`) |
|----------|-----------------------|
| `35`     | sets to **35** (absolute) |
| `+5`     | **35** (add to current) |
| `-10`    | **20** (subtract) |
| `30+5`   | **35** (evaluates the expression) |
| `(4+1)*3`| **15** |

Values are clamped to their limits: ability scores **1–30**, class level **1–20** (total across classes also capped at 20), HP/speed **≥ 0**, current HP **≤ max HP**. (AC is auto-calculated, not a bounded number box — see HP & Defenses below.)

## Modules
*(The strip of **character tabs** above the modules isn't a module — it belongs to the sheet as a whole. See [Characters](#characters-tabs-creation-levelling-up).)*

- **Character** — name, race, subrace, background, and a multiclass table (each class + subclass + level + Hit Die + Casting type). Hit Die and Casting type default to **auto** — looked up from the SRD class/subclass name you type (see [Where game data comes from](#where-game-data-comes-from)) — and can be set explicitly to override the lookup. Total level auto-drives **proficiency bonus** (with an override box).
- **Ability Scores** — three columns: **Base**, **Misc**, and the live modifier. Base is what the character creator and level-up set, and is **read-only** — it's the number you actually built, not a scratchpad. Everything since goes in **Misc**, which takes a list of signed terms, each optionally labelled with what it's from: `+4-1` nets +3, and `+2 belt, -1 curse` does the same while recording why. (Numbers are read first, and the words after each one up to the next number or comma are its label, so both shapes work under one rule; a hyphen inside a label survives as long as it isn't followed by a digit, which keeps `half-plate` readable.) The total appears beside the base as `= 18` whenever Misc or a feature has moved it — hover for the full breakdown, base and every labelled term and every feature that contributed.
- **Saving Throws** — proficiency toggle + misc bonus → auto total, with a roll button. The **Misc** field accepts dice (e.g. `10+1d4`).
- **Skills** — proficiency / expertise (mutually exclusive) + misc → auto total + roll button. Passive Perception computed. The **Misc** field accepts dice (see [Roll buttons](#roll-buttons)). Rows **drag to reorder** by the grip at the left: most skills never come up, so put the ones you actually roll on top. The order is saved with the character (so a rogue and a wizard can differ, and it travels with an export), and **reset to alphabetical** puts it back.
- **HP & Defenses** — current/temp HP, speed, auto initiative + roll button, and **Hit Dice** (see [Resting](#resting) below — one pool per class, with a roll button that spends one, heals, and logs the roll). **Max HP** is auto-calculated from each class's Hit Die & level (fixed/"consistent" value per level, not rolled) + CON mod per level, with an override box. **AC** is likewise auto-calculated (like initiative) from your equipped armor in the Inventory module: no armor equipped → 10 + DEX; light armor → armor AC + full DEX; medium → armor AC + DEX (capped at +2); heavy → armor AC alone; any equipped shield adds a flat +2 (shields don't stack). A misc field and an override box cover everything the formula can't — Unarmored Defense, natural armor, magic items not itemized in Inventory, etc.
- **Conditions** — a stacked list of toggles for the 14 conditions (hover any for a multi-line effect reminder). Checking **Paralyzed, Petrified, Stunned, or Unconscious** also flags **Incapacitated** (which they each impose).
- **Exhaustion** — a clickable 0–6 effect table: click a level to set it (click your current level to step down), with rows up to your level highlighted since the 2014 effects are cumulative.
- **Death Saves** — 3 success / 3 failure boxes, plus a **Roll Death Save** button that rolls 1d20 to the Event Log and auto-marks a box (10+ success, &lt;10 failure, nat 20 clears saves and sets HP to 1, nat 1 marks two failures).
- *(Conditions and Exhaustion now feed the sheet's math — see [Conditions and exhaustion](#conditions-and-exhaustion). Death Saves remain a display-only tracker.)*
- **Combat** — the round tracker: what's left of your action, bonus action, reaction, object interaction and movement this turn, with a menu per resource of what you can spend it on. See [Combat rounds](#combat-rounds).
- **House Rules** — the table's ruleset: banned spells/items/subclasses, excluded sourcebooks, and campaign settings like point buy or feats-off. Shared by every character tab rather than owned by one. See [House rules](#house-rules-bans-sources-campaign-settings).
- **HP & Defenses** also carries the **Guidance / Resistance / Death Ward** counters, which stack and fold their d4s into the matching rolls. See [Boons](#boons-guidance-resistance-death-ward). Below those sit three boxes — **Resist / Immune / Vulnerable** — for anything you have that no feature granted: someone else's spell, a potion, an item not itemised in Inventory, a DM ruling. Comma-separated and deliberately free text, since "bludgeoning from nonmagical attacks" is a thing tables say and no picker would offer it. What you type joins whatever your features already grant, and a duplicate shows once.

Below those sits a **defences line** the [feature-effects engine](#feature-effects-automatic-mechanics) fills in from what your race, class and feats actually grant: extra movement speeds (as a number where the rules give one, as their own words where they don't — "equal to your walking speed"), damage resistances / immunities / vulnerabilities, conditions you have advantage on saves against, and a **Situational** line for advantage that depends on terrain, lighting or what another creature is doing. The Situational entries are listed and credited, never applied — the sheet can't see the trigger.
- **Inventory & Equipment** — coin purse (cp/sp/ep/gp/pp, auto-summed to a gp total via SRD exchange rates), plus a Features-styled item list: each line shows qty, name (click to show/hide its description, looked up from the Equipment Library by name), equipped toggle, and — for items that require it — an attuned toggle, with an **Attuned X/3** counter above the list. Items are added only from the Equipment Library (click "+ Add Item" to open it), same as Spells below; weight/value are looked up live from the library entry, not hand-edited. The **quantity box is editable** — type into it and the row's per-item and total weight/value follow as you go. The footer totals weight and item value, and shows **total wealth = coins + items** in gp.

  *Equipped slots (PHB p141).* Above the list is a paper doll — main hand, off hand, armour, headwear, cloak, gloves, bracers, footwear — one item each, because that's what the rule says: you can't normally wear more than one pair of footwear, one pair of gloves, one pair of bracers, one suit of armour, one item of headwear, or one cloak. Click a slot to see what fits, or **drag** an item from the list onto it (and drag it back off to unequip). A **two-handed weapon takes both hands**, and putting something in the off hand displaces it.

  The same page says to use common sense and allow exceptions — a circlet under a helmet — so every picker has a **show everything** toggle and will take whatever you insist on. Slot suggestions come from the item's type where the data types it (armour, shields, weapons) and from its name where it doesn't, since 5e.tools has no body-slot field: *Winged Boots* and *Boots of Speed* are both footwear. Ticking **equipped** in the list still works and drops the item into its guessed slot; unticking empties the slot. A character from before slots existed keeps everything it had equipped, placed into the slots it fits.

  A **thri-kreen**'s two secondary arms appear as extra slots that hold objects but refuse weapons and shields, per that race's own wording; there's a toggle to turn extra arms on for anything else that has them.

  *Adding a generic variant.* 5e.tools stores some entries as *categories* rather than items — "Armor of Resistance" is really the ten concrete items it stands for, and "Cast-Off Armor" likewise. Those have nothing to say about weight, value or AC, so adding one by name would put a dead line in your inventory. Their button is a **…** instead of a **+**: it expands the category's members inline and each of those is addable. A member whose own book isn't loaded is still offered (marked `*`) and added by name.
- **Proficiencies** — armor (Light/Medium/Heavy/Shields) and broad weapon (Simple/Martial) category checkboxes, plus freeform add/remove lists for specific weapons, tools, and languages.
- **Attacks** *(draft)* — a weapons table. Per attack: an ability (Str / Dex / **Finesse** = higher of the two / —), a proficiency toggle, an **Fx** toggle (below), and Hit+/Dmg+ fields (flat or dice). From those it computes the to-hit bonus and the damage expression and gives roll buttons for each — plus an **atk+dmg** button on the far right that rolls the attack and its damage together as one log entry. The to-hit button rolls through the shared engine, so Shift/Ctrl and the right-click menu give advantage/disadvantage. A lone attack's crit is flagged in the log but doesn't auto-double its damage dice (you do that by eye); Offensive Routines below handle crit doubling automatically.
  - **Fx — your [feature effects](#feature-effects-automatic-mechanics) on this weapon.** With Fx ticked (the default), the effects engine's `attack-hit` and `damage-bonus` targets fold into that row exactly like its own Hit+/Dmg+ fields, and a forced advantage/disadvantage on `attack-hit` sets the to-hit button's roll mode. That covers Sharpshooter and Great Weapon Master's −5/+10, Rage's damage bonus, Divine Strike, Improved Divine Smite, Hexblade's Curse, Reckless Attack, Vow of Enmity, Steady Aim, Guided Strike and the rest. The engine has no per-weapon predicate — it's one global bucket — so **untick Fx on any weapon a bonus doesn't belong to** (Sharpshooter on your dagger, Rage on your longbow). Nothing is applied silently: a button whose number includes an effect is underlined and its tooltip names every contributing feature plus any reminders the entry carries ("melee weapon attacks only", "once per turn"), and the Event Log gets the same `[Feature +N]` annotations as the rest of the sheet.
- **Offensive Routines** *(draft)* — program a turn once and fire it with one click. A routine is a named list of steps: **attack steps** reference a row in the Attacks module with a count (*2× Halberd* for Extra Attack, plus *1× Halberd* for a Polearm Master bonus action), and **save steps** cover save-based effects like Toll the Dead or Fireball — no to-hit roll; instead of guessing pass/fail against a hidden target bonus, they roll the target's d20 and report it as a break-even threshold on the target's own save bonus (the DC follows your own spell save DC by default, or set a custom one per step). Running a routine emits one log entry: a **damage-by-AC-range table** up top (how much total damage the routine does against AC 0–15, 16–19, 20+, etc., derived from each attack's actual to-hit total so it adapts to whatever ACs the swings happen to beat) with the individual swing/save rolls tucked into a collapsed details block below. Crits **auto-double their damage dice** in this table (unlike the standalone atk+dmg button). Shift-click **run** for advantage on every attack in it, Ctrl for disadvantage. Attack steps reference attacks by a stable id, so renaming or reordering your attacks won't break a routine (deleting one leaves the step visibly marked instead of silently mis-rolling).
- **Companions & Summons** — statblocks you play with (familiars, steeds, wild shapes, and above all summons), each tracked as a *stack* of creatures with individual HP, roll buttons on every attack/save/skill, an **×N all** button that rolls a whole stack of summons at once into a damage-by-AC table, and live scaling for Tasha's-style summons off your own spell attack bonus and cast level. See [Companions & summons](#companions--summons-bestiary-import).
- **Event Log** — the running record of what has happened to this character: every dice roll, plus rests and (as more mechanics land) other notable events. Its input box doubles as the dice roller's command line — see [Event Log (and the dice roller)](#event-log-and-the-dice-roller).
- **Features** — import race/class/feat data to see the traits and features your race, subrace, and classes/levels grant, plus a feat picker for Ability Score Improvements. Also home to the **Short Rest** / **Long Rest** buttons (see [Resting](#resting)) and **Level Up** (see [Characters](#characters-tabs-creation-levelling-up)). Spell grants (Cleric domain spells, Mark of \* traits, Eldritch Knight/Divine Soul/Warlock-patron/Wizard-subschool spell-list expansions, etc.) show as clickable spell names alongside the granting trait, in two flavors per 5e.tools' own data: free/innate grants (e.g. Cleric domain spells) add straight to Spellcasting under their own header, separate from and not counted against any class's Known/Prepared total; **list-expansion** grants (marked with a trailing `*`, e.g. Dragonmark or Eldritch Knight spells) only make the spell *eligible* — clicking one opens a dialog asking which class you're preparing/learning it from, and it's added as a normal spell for that class (counts toward its Known/Prepared total, shows a prepared checkbox if applicable), annotated with its granting trait's name for reference. Some grants aren't a list of names at all but a *filter* — "every EGW spell" (Chronurgy Magic), "any Wizard cantrip" (Eldritch Knight), "any level 0–3 spell, choose 1" (College of Lore). Those can't be click-to-add, so they're shown in italics as a plain description of what you're entitled to; add the ones you actually use from the Spell Library.
- **Spellcasting** — spellcasting ability → auto save DC & spell attack; a collapsed **Spell Library** subsection (click "+ Add Spell" to open it) for importing & searching spells; spell-slot grid **auto-calculated from total casting level** (per the multiclass spellcaster table — Warlock/Pact levels aren't included, since Pact Magic is a separate slot pool), with a per-level override box; a Features-styled **Spells** list (grouped by class, added only from the Spell Library) with a known/prepared/cantrip counter per class, plus a separate group per granted-spell source (domain/subrace). Any added spell the library flags as requiring **concentration** gets a small **conc** toggle next to it; turning one on shows an always-visible "🔒 Concentrating: *spell*" banner above the list with its own **drop** button, and turning on a second concentration spell automatically drops whichever one was active (5e only allows one at a time) — tracked by spell name, so it survives reorders/reloads, not by list position.

## Event Log (and the dice roller)
The Event Log is the sheet's running history: dice rolls land here, and so do actions that involve no dice at all — taking a short or long rest, for instance, records what it restored. Newest entry on top. Entries are tagged by kind (`roll`, `rest`, `hp`, `resource`, `condition`, `info`) and non-roll kinds get a coloured left rule so they're scannable in a stream of rolls; rolls themselves render exactly as they always have.

*This module still carries `data-module="dice"` internally — [layout.js](src/layout.js) keys saved module positions off that attribute, so renaming it would orphan every saved arrangement.*

**Adding events from new mechanics:** the whole API is one call, `logEvent(kind, html)` in [src/event-log.js](src/event-log.js) (`log(html)` is the back-compatible shorthand for `logEvent("roll", html)`). That file's header comment carries the list of mechanics that *should* report here and don't yet — conditions and exhaustion changing, concentration starting/breaking, spell slots being spent on a cast, limited-use pips, death-save outcomes, XP being awarded — each a one-line call to add when that feature is next touched. (Resting, character creation and levelling up already report.)

**Dice roller.** The same box takes roll commands. Type one and press **Enter**. Prefix is `/` (also accepts `!`). Bare notation works too (`4d6kh3`).

| Command | Meaning |
|---------|---------|
| `/r <roll>` or `/roll` | roll dice |
| `/rr <N> <roll>` or `/multiroll` | roll N times (N and roll may be swapped if no label) |
| `/rrr <N> <DC> <roll>` or `/iterroll` | roll N times, count successes vs DC |
| `clear` | clear the log |

**Roll syntax** (5eCrawler / Avrae compatible):
- Dice: `2d6`, `1d20+5`, `2d6+1d4+3`, `1d4*2`, with `+ - *` and parentheses.
- Keep/drop: `4d6kh3` (keep highest 3), `kl`, `ph`, `pl`, `k>4`, `p<2`.
- Reroll: `ro` (once), `rr` (infinite), `ra` (reroll & add). e.g. `8d6ro<3`.
- Explode: `e` (on max) or `e6`. Min/max each die: `mi2`, `ma5`.
- `adv` / `dis` — rolls the d20 with advantage/disadvantage (ignored if there's no d20).
- Label: any text after the roll (`/r 1d20+7 Stealth`). Annotations: `4d6mi2[fire]`.
- A single term is capped at **500 dice**, so a mistyped `1000d6` can't lock the tab up. Hitting the cap is stated in the roll's own log line (`[capped at 500 of 1000 dice]`) rather than silently returning a smaller number — a truncated roll presented as a correct one is exactly the kind of quiet wrongness the rest of the sheet avoids.
- Labels and `[annotations]` are escaped before they reach the log. They can carry a weapon or spell name typed by you or read from an import, and the log stores its markup and replays it on every load, so text that happens to look like HTML is shown as text.

**Crits:** only the kept **d20** triggers *Critical Success* (nat 20) / *Critical Failure* (nat 1) — other dice never do. (This deliberately fixes a 5eCrawler bug.)

### Roll mirror (the corner panel)

**This is the primary rolling surface.** A panel pinned to the **bottom-right** shows the newest entries and carries the same command line the Event Log module has, so a roll is readable and repeatable without leaving what you're doing. The command box sits **above** the entries, next to where its own result will appear — the log reads newest-first from the top, so a box at the bottom would have been a list-length away from what it produces. The Event Log module itself starts **folded** on a fresh install — it's where you go to read back through history, not something that needs to be open. (An existing layout is untouched: only a first run gets the fold.)

It is a mirror and nothing else: every entry in it was put there by the same call that writes the module, switching characters repaints it from that character's own stored log, and clearing the log clears it. It keeps the last 40 entries; the module keeps the full history. Drag the **grip in its top-left corner** to resize it — up and left makes it bigger, which is the only direction that doesn't push a bottom-right-anchored panel off the screen; the size is remembered. **▼** folds it to its title bar, **×** hides it and leaves a small **Rolls** tab to bring it back — and an actual *roll* arriving while it's hidden reopens it, since that's exactly the moment you want it. Nothing else does: loading a house-rule preset, taking a rest, ticking a condition and every other kind of log entry leave a hidden panel hidden, so an unrelated click elsewhere on the sheet can't pop it back open with no explanation. Folding is left alone regardless, because folding is a deliberate "I know it's there". Both settings are per browser rather than per character, and it doesn't print.

### Tumbling dice

A new roll flashes before it settles: each die face runs through a few other faces **of its own die** and then lands on what was rolled, with the total recomputed live from whatever is showing at that moment. It's there to catch your eye when the result arrives somewhere you weren't looking.

**Dropped dice tumble too, and the strike-through moves with them.** Roll with advantage and you watch the two dice fight over it: whichever is momentarily higher is the kept one, the other is struck through, and the total follows — all of it re-running the roller's own keep/drop rule against what's currently showing, not a second rule written for the animation.

Two things deliberately don't move. **Modifiers and signs** never flicker — watching a fixed `+5` jitter reads as the sheet being unsure of it. And the **result** is not in play at all: every number was rolled before the first frame drew, and nothing in the animation can reach it. What you see mid-tumble is theatre; what it lands on is the roll.

The running total is computed, not faked. Each die term's effect on the total is measured when the roll happens (bump it by one, see what the total does), so `20-1d6` counts *down* as the die climbs and `2*1d6` moves in twos; the total is summed per *term* from whatever that term is currently keeping, which is why a moving strike-through needs no special case. Both copies of an entry — the module and the corner panel — are driven from one sequence, so they can never show different numbers at the same moment.

It runs off the log itself, which means every path that rolls dice gets it: the command line, roll buttons, attacks, companions, routines, rests, death saves.

**The ⚅ button in the roll mirror's title bar switches it on and off.** If your system asks for reduced motion the animation starts off — but that only sets the default, and the button overrides it, because a feature that silently isn't there is worse than one you can turn off.

## Roll buttons
Every save / skill / initiative / spell-attack has a `roll` button that uses its computed bonus.
- **Shift-click** = advantage, **Ctrl-click** = disadvantage.
- Hold **Shift / Ctrl** while hovering a roll button to see the active mode as a tooltip.
- **Right-click** a roll button for a *Normal / Advantage / Disadvantage* menu.
- A stat's **Misc** field may contain **dice** (e.g. `10+1d4`): the flat part folds into the shown total, and the dice are appended to the roll — handy for always-on effects like Pass Without Trace + Guidance on Stealth.

## Combat rounds
Rolling initiative puts you in combat, and the **Combat** module starts tracking your turn: action, bonus action, reaction, free object interaction, and movement in feet. **End Round** gives it all back. It's the round tracker from LANCER's COMP/CON, applied to 5e's action economy.

Each resource is a button. **Click** it for a menu of what you can spend it on — built from *your* sheet, not a generic list: your attacks, your spells filtered by casting time, your class features that mention a bonus action, plus the standard PHB actions (Dash, Disengage, Dodge, Help, Hide, Ready, Search, Use an Object). Picking something spends the resource and, where the sheet can, makes the roll — Hide rolls Stealth through your real skill button, an attack rolls that attack. **Double-click** a resource to just spend it with no menu, for when you know what you did and only want the pip gone. A menu row shows only the action's name; hover it for what it actually does (bonus, damage, disabled reason) as a tooltip, the same "name first, details on hover" pattern as a roll button or an Attacks row's **Fx**.

**Undo** sits next to End Round. It reverses exactly the last thing you spent — one level, not a history you can step back through — and covers a compound spend (Dash, or taking Attack with no swings banked) as a single step, since those touch several pools at once and undoing only part of one would leave the tracker in a state you never actually had. It does **not** remove the Event Log entry the spend made; erasing history would fight the "every spend is logged, so the record is auditable" idea two paragraphs down, so Undo adds its own log line instead — both "this was spent" and "then undone" stay on the record. Undo only reaches back within the current round: ending a round refreshes everything on purpose, and a stale "undo" against a turn that's already over would restore the wrong turn's numbers, not yours.

**The Attack action grants swings, not one attack.** Taking it banks 1 + Extra Attack attacks, and each attack roll spends one — so a Fighter 5 rolling twice has used *one* action, which is the whole point. Rolling an attack with nothing banked takes the action first and then a swing, so the common case (click **atk+dmg**, never touch this module) books itself correctly. Extra Attack is read from your class features, including Fighter's escalating "Extra Attack (2)" and "(3)".

The menus know a few things worth knowing:
- **Two-Weapon Fighting** (PHB p195) is offered only when you have two *light melee* weapons equipped and have already attacked this turn — and says which condition is missing when it isn't. A dagger counts: it's a melee weapon that happens to be thrown.
- **Cast a Spell** appears under whichever resource matches the spell's casting time, with the matching spells in a submenu. A spell your Spell Library doesn't know is left out rather than guessed at.
- **Dash** adds your speed to the movement pool rather than doubling it — same result, and it survives a speed change mid-turn.

**Movement** is its own resource, spent in feet rather than as one of the four pips, and its whole row sits below the pips rather than behind a menu: **−5 −1** [ *current*/*max* ft ] **+1 +5**, with the current/max box **directly editable** — type the feet you have left and tab out, the same override-box pattern as Hit Dice's remaining count — for nudging a distance a foot at a time or correcting it outright. The **⋯** button next to it still opens a menu for the presets (5/10/15/30 ft, your full speed), Dash, and standing up from prone.

A **terrain** multiplier prices all of them, in its own box right beside the movement box (**×** followed by a number — type anything, 1 for normal ground, 2 for difficult terrain or crawling or standing in a creature's space, PHB p182; 3 for two of those stacked; 4 for *Plant Growth*). Everything you enter through the steps or the menu presets is **distance**, and the pool is charged distance × multiplier, so a 10-ft step through difficult ground correctly spends 20 ft without you doing the arithmetic. It stays set across moves and across End Round, since terrain is a property of the ground you're standing on rather than something you re-declare each turn; it clears when you leave combat or start a fresh one, same as everything else the tracker resets. Standing up from prone is unaffected — PHB p190 prices it as half your speed stat, not as distance covered, so there's nothing for the multiplier to apply to.

**Speed** is never blank, because a blank Speed is a Movement pool that reads 0/0. The field ships at 30 ft, and it follows the **Race** box: pick Halfling or Dwarf and it becomes 25, pick a race whose data lists several movement types and it takes the walking one. The moment you type your own number it stops following — the sheet remembers what it last put there, and once the box holds something else it never touches the field again. Loading a character saved with an empty Speed refills it the same way, so characters made before the field had a default come back working rather than at 0/0. If the Race Library has nothing for the race — most often because the sheet was opened straight from disk rather than through a server, so the automatic `data/races.json` load never ran (see [Where game data comes from](#where-game-data-comes-from)) — it falls back to 30 ft, the walking speed of most PHB races. The character creation wizard fills the same number in at creation.

The pool tracks Speed **while a fight is in progress**: change your Speed (or an effect that feeds it) mid-turn and the max moves with it, keeping the feet you've already spent. The row isn't redrawn to do it — it holds live text boxes, and repainting them on every keystroke would take the caret with it — so only the two numbers are rewritten in place.

**Nothing is enforced.** A resource at zero goes red and says you're over, and the roll still happens. Readied actions, Action Surge, and effects this sheet doesn't model are all real, and a tracker that refused to let you roll would be wrong often enough that you'd turn it off. Every spend is logged to the [Event Log](#event-log-and-the-dice-roller), so the record is auditable.

*Two documented simplifications.* Your reaction actually refreshes at the **start** of your turn (PHB p190), not the end; since the initiative order below tracks whose turn it is but not anyone's resource pools, one End Round button standing for "end my turn / start my next" is the honest version, and the button says what it refreshes. And the free object interaction is one per turn — a second one costs your action, which is the separate **Use an Object** entry.

The tracker's own pools are per character, so switching to your familiar's tab shows that character's own turn, and a fight survives a reload. The initiative order below is the exception — it belongs to the table, and is shared by every tab.

**Initiative order.** A plain list — name and initiative, highest first — sits above the rest of the module, shown whether or not combat is active so a DM can build it before the first roll. **Roll Initiative** (HP & Defenses) seeds or updates your own row with the number that actually landed in the Event Log, never a second private roll that could disagree with it; re-rolling updates it in place rather than adding a duplicate, and every character on your roster gets their own row rather than fighting over one. Add anyone else — a monster, an ally at the table, an NPC — by name and initiative in the boxes below the list; both a row's name and its number are edited in place and re-sort on commit. **× ** removes an entry. **Next turn** steps to the next name in the (sorted) order, wrapping back to the top after the last one and highlighting whoever's up; wrapping is announced in the log but deliberately doesn't touch the round counter or reset anyone's pools — this list tracks *whose turn it is*, not *that character's own action/bonus/reaction/movement*, which stays End Round's job for the pools this sheet actually models (yours). The list belongs to **the table, not to a character**: like [House Rules](#house-rules-bans-sources-campaign-settings), it is shared by every character tab and kept under its own storage key, so stepping the turn on one tab is the same fight you see on the next. (It lived inside the per-character combat state at first, which meant two PCs each kept a private order and switching tabs mid-fight showed an empty one; an order saved that way is adopted into the shared list the first time it loads rather than being dropped.) A row belonging to a character is labelled **(you)** on that character's own tab and **(pc)** elsewhere, and its name box is read-only — it follows the character's name, so renaming them renames the row without another roll. It's still a local, single-browser list — not yet shared across players' own copies of the sheet, which is the [multiplayer VTT](#eventual-goal-self-hosted-multiplayer-vtt--ai-table-companion)'s job.

## Conditions and exhaustion

Ticking a condition used to record it and change nothing. It now moves the numbers — and, just as importantly, says which parts it is **not** moving.

**Applied.** Advantage and disadvantage on *your own* d20 rolls (Poisoned, Frightened, Blinded, Prone, Restrained, Invisible), your **speed** (Grappled, Restrained, Paralyzed, Petrified, Stunned and Unconscious all stop you), and — via exhaustion — your **hit point maximum**. Exhaustion follows PHB p291: disadvantage on ability checks at 1, speed halved at 2, disadvantage on attacks and saves at 3, hit point maximum halved at 4, speed 0 at 5. Advantage and disadvantage cancel however many of each you have (PHB p173), so a Poisoned rogue attacking from Invisible rolls straight.

**Listed, not applied**, with the reason in each case:

- *"Attack rolls against you have advantage."* That's someone else's roll. The sheet has no model of being attacked, and inventing one to hold a number nobody rolls here would be worse than a sentence.
- *"You automatically fail Strength and Dexterity saving throws."* An auto-fail is not disadvantage, and dressing it as disadvantage would be a lie that sometimes succeeds.
- *"You can't take actions or reactions."* The round tracker is advisory by design and never blocks a spend; zeroing your action here would be the one place the sheet started refusing.

Two lines under the condition list keep those apart: **Applied** is what the sheet has already done to your numbers, naming the condition responsible, and **Yours to apply** is what it's leaving to you. Frightened is applied even though it only bites "while the source is in line of sight", because being frightened of something you can't see is the unusual case — the note says so.

## Boons: Guidance, Resistance, Death Ward
Counters in the HP & Defenses module, below Roll Initiative. They're **counts, not toggles**, because at this table these spells stack — see [house rule R21/R22](#house-rules-bans-sources-campaign-settings) and `house-rules/lampmann.md` §4.9 for the full argument. The short version: Combining Magical Effects (PHB p205) suppresses the older of two identical spells rather than ending it, a spell's end condition lives in its *effect* rather than its *duration*, so a suppressed Guidance has its "the spell then ends" suppressed too. Expend the active one and the suppressed one wakes up with "after making the ability check" still true — so it can be expended on the same check. Hence N d4 on one roll.

| Boon | Applies to | Effect |
| --- | --- | --- |
| **Guidance** | ability checks — every skill, plus **initiative** (PHB p189 defines it as a Dexterity check) | +1d4 per casting |
| **Resistance** | saving throws | +1d4 per casting |
| **Death Ward** | nothing rolled | dropping to 0 HP leaves you at 1 instead |

The dice are folded in through the same path as the Misc field and feature effects, so a skill showing `+6 +2d4` is stating exactly the expression its roll button will use — the display and the roll can't disagree. Attack rolls, AC and a companion's own rolls draw on none of them.

**A roll spends every active die of the matching kind.** Stacking three Guidances is something you do deliberately, right before the check you care about, so "spend them all" is the case worth optimizing; spending one of three means editing the count down, rolling, and putting it back. Every spend is logged with what it added, and the counts are ordinary editable boxes (the same correct-it-directly rule as Hit Dice), so an unwanted spend is one keystroke to undo rather than a mode you had to know about first.

**Death Ward fires by itself** when your current HP drops to 0: you go to 1 instead, one ward is spent, and the Event Log says so and how many are left. It triggers on the *transition* to 0, not on being at 0 — so sitting at 0 doesn't burn a second one, and switching character tabs or reloading never fires one. With no ward up, 0 is 0.

**Rests.** Guidance and Resistance last a minute, so no rest of any length leaves them running. Death Ward runs 8 hours — exactly a long rest — so a short rest leaves it alone and a long one ends it.

Boons are **per character**, saved with that character: two characters can each be under their own Guidance, and switching tabs shows the right one.

**Stacking is a house rule, and it's switchable.** *Guidance / Resistance stack* under [House rules](#house-rules-bans-sources-campaign-settings) is on by default, because that's the reading argued above. Switch it off and **the Guidance and Resistance counters come off the sheet entirely** — they were counters only because they stack, and without that "how many are running" collapses to a yes/no, so a box that can count to three in a game where three means nothing is worse than no box. No roll draws on them while it's off, even if a count is left over from before the ruling flipped; switch it back and both the counters and the count return. **Death Ward is deliberately not covered** and stacks either way — it was never a die stacked onto a roll, it's how many times you get pulled back from 0 HP, which is worth counting under any reading. Lampmann's preset ships with stacking **off**.

**Concurrent-casting counters.** A counter like **Planar Binding /1** appears when the ruleset caps how many castings of a spell you may have running at once — that one is house rule H4, and it's in Lampmann's preset. It counts what *you* have up; the limit beside it belongs to the table. Going over turns it red rather than stopping you, same as everything else here. A table with no such caps sees none of these.

**Custom counters.** **+ Counter** at the end of the row adds one of your own: a name, an optional max, and the same ±/type-in box as the rest. For anything the sheet doesn't model — charges on a DM-invented item, arrows left, favours owed to an archfey, points on a homebrew subclass. The max is advisory (over it goes red), and **×** removes the counter. They're per character and saved with it, like every other counter in this row.

## House rules (bans, sources, campaign settings)
The **House Rules** module holds the *table's* ruleset rather than any one character's. It is shared by every character tab, persists to its own storage slot, and is deliberately **not** included when you export a character — a character handed to another table gets played under that table's rules, not the one it was built at.

Nothing here blocks a roll. A ban greys out an Add button and marks a row; it never takes away a character you already have, and it never stops you playing one. Same reasoning as the [combat tracker](#combat-rounds): a sheet that refused would be wrong at exactly the moment the DM said "yes, fine."

Three tabs.

**Bans** — one list per kind (spells, items, classes, subclasses, races, backgrounds, feats, and a free-text **Other** for rules with nothing behind them in any library, like a banned character-creation option or a whole strategy). Each list has a combobox that type-aheads over that library, so banning something is a couple of keystrokes rather than an exact-name recital; free text is still accepted for anything your data doesn't cover. Names match case-insensitively and ignore the source, because banning Fabricate means banning it in every printing. Subclasses are listed as `Class: Subclass` since two classes can print the same subclass name.

**Banned entries are always shown, never removed.** A ban is information you need at the moment you would have picked the thing, and an option that silently vanishes reads as missing data with no way for the sheet to say why. So:

- In the **Spell and Equipment libraries**, a banned row is struck through and tagged `banned`, with its Add button disabled and a tooltip saying why. Both libraries also gain a **House Rules** filter group, so a player who would rather not see them can exclude banned entries with the same tri-state control they already use for everything else, instead of learning a separate hide-banned mode.
- In every **picker** — the creator's race, subrace, class, subclass and background boxes, the level-up class box, the Character module's own race/class/subclass fields, and each ASI feat slot — a banned option is listed in red and flagged `banned`, and is still selectable. An input already *holding* a banned value goes red too, with a tooltip, so a character carrying one keeps saying so long after the picker closed.

Subclass bans are stored qualified (`Fighter: Champion`) and matched that way, so banning one class's subclass leaves an identically-named subclass on another class alone — and the qualifier follows whatever class is typed in that row as you change it.

**Sources** — a **denylist**, not an allowlist. Every book starts allowed and you name the exceptions, because "everything official except a few" is how most tables actually run, and a hand-maintained allowlist of a hundred-odd books goes stale with every release. A banned book bans everything printed in it, and the tooltip on an affected entry names the book rather than claiming a name ban. The grid lists whatever your loaded libraries actually contain, so it tracks your data rather than a hardcoded table.

**Settings** — campaign defaults. Each says whether the sheet actually reads it or whether it is *recorded only*, so nothing pretends to be enforced when it isn't. Currently enforced: the **ability score method** (the creator opens on it), **multiclassing** (off hides the creator's add-a-class control), **feats** (off means ASI only — the feat picker disappears from ASI slots, though a feat already chosen is kept, since switching the rule on later must not silently strip a character built under the old ruleset), **magic item prices**, and **oversized weapons** (below). Recorded only: average HP, optional class features, hirelings.

**Oversized weapons** (R17) needs two sizes to compare, so the sheet now carries both: **Size** in the Character module (your creature size, filled in by the creator from your race) and a **Size** column on each Attacks row (the size the *weapon* is made for — leave it blank for ordinary gear). The extra damage dice belong to the weapon, so nothing here touches damage; a greataxe sized for a Large creature is 2d12 for whoever swings it, and that's just what you type in the Damage box. Only the penalty and the limit depend on who's holding it:

| Setting | One size too big | Two or more |
| --- | --- | --- |
| **Fully allowed** *(default)* | disadvantage | disadvantage |
| **Not if 2+ sizes larger** | disadvantage | flagged unusable |
| **Banned** | flagged unusable | flagged unusable |

Disadvantage is real — the to-hit button rolls `2d20kl1` and labels the entry `(oversized)`. Advantage from a feature and disadvantage from an oversized weapon cancel to a straight roll (PHB p173) rather than one overriding the other. "Unusable" is stated in the Size cell's tooltip and colour; the button still rolls, because the DMG frames that limit as a suggestion ("you can rule that…") and the DM is at the table.

**Magic item prices** offers XGtE's asking-price table with the **mean** of each die expression taken, so prices are fixed rather than rolled per item — 45 / 350 / 11,000 / 35,000 / 175,000 gp by rarity, halved for consumables per XGtE's own footnote. It overrides a *printed* price too, which is what separates it from the library's own rarity fallback (same figures, but only used when the source data names no price at all). Artifacts, "unknown (magic)" and mundane gear have no entry and are left alone. **Trinkets are worth 0 gp** is a separate toggle (R9), recognising trinket-table entries by 5e.tools' own tag and falling back to the name. Both reach the inventory's value total, not just the library's Cost column.

**A bonus-action spell always costs a bonus action** (R47) makes the Combat tracker's *Cast a Spell* entry unavailable under Bonus Action once that action is spent, saying so rather than just greying out. The reading it rejects takes PHB's "you must use a bonus action… provided that you haven't already taken a bonus action this turn" as *lapsing* once you have — making the spell free rather than uncastable.

**Concurrent castings** caps how many of a named spell may be running at once (H4 — "only one Planar Binding per character"). Stored as a table rather than special-cased, so any spell can be capped, and each one gets a counter beside your HP. Going over is shown in red and labelled *over*; it is never prevented.

**Starting equipment must be mundane** (R35) is stated on the creator's equipment step, where the open-ended "any martial weapon" picks are actually made. The sheet can't police it — it never learns which inventory line filled which slot — so this is a statement at the point of choice rather than a check.

**Optional rules** — 5e.tools' own catalogue of the books' RAW alternatives: Flanking, Cleaving Through Creatures, Gritty Realism, Proficiency Dice, Variant Encumbrance, Hero Points, Spell Points, Facing, and about seventy more. These are a different thing from the Rulings tab next door, and the distinction is the point: a *ruling* is one table's reading of ambiguous text, while these are printed options the books themselves offer — the same everywhere they're switched on.

Imported, never bundled, exactly like the spell and equipment libraries: the catalogue comes from your own `data/variantrules.json` (see [Where game data comes from](#where-game-data-comes-from)), so nothing here hardcodes a rule's text and a data update is picked up for free. Filter by book, by whether the books mark an entry Optional/Variant, or down to just what your campaign uses; search covers names and full rule text; **…** expands the rule inline. The switched-on set travels in an exported ruleset.

Most of the 116 are DM-facing procedure — Morale, Plot Points, downtime activities — with nothing for a character sheet to compute, so they are marked *recorded only* and switching one on records the choice and shows its text. Four genuinely change your numbers and say so:

| Rule | What switching it on does |
| --- | --- |
| **Variant Encumbrance** (PHB p176) | Speed drops 10 ft past 5× your Strength score, 20 ft past 10×, with the status shown beside your HP. The heavily-encumbered disadvantage is stated rather than applied — it depends on which ability a roll uses, and the sheet has no per-ability disadvantage channel. |
| **Proficiency Dice** (DMG p263) | Skills, saving throws and attack to-hit trade the flat proficiency bonus for a die (d4 at PB 2 up to d12 at PB 6). Expertise rolls it twice rather than doubling, per the rule's own wording. Passive Perception necessarily keeps the flat number — there's no roll to make. |
| **Hero Points** (DMG p264) | A counter beside your HP with the level-scaled maximum (5 + half your level). Spending stays manual: a hero point is spent *after* the d20 lands, so folding a d6 in beforehand would be the wrong shape. |
| **Rest Variants** (DMG p267) | Pick Gritty Realism or Epic Heroism under Settings; the Short/Long Rest buttons then state their durations. The entry offers two named variants, so switching it on isn't a choice by itself. |

Four more are marked *set elsewhere* — Feats, Multiclassing, Optional Class Features and Customizing Your Origin already had controls before this catalogue existed, so the entry points at them rather than adding a second switch that fights the first.

**Rulings** — the part of a ruleset that can't be a checkbox. Most of what a table decides is adjudication ("Total Cover applies to all effects", "a Challenge Rating of — is not equal to itself"), and there's a failure mode in only ever building the automatable half: the Bans tab has buttons, "ability checks are only called for when the outcome is uncertain" has nothing to click, and over time the rules with switches start feeling like the real ones. Three things guard against that.

- **Every ruling is listed, and each says which it is.** One the sheet applies is marked *the sheet applies this*, with a tooltip naming the part that does it; the rest are marked *yours to apply* — a label, not the absence of one. The header states the split and points out that the second number is the larger one on purpose.
- **Grouped by subject and searchable**, so a ruling is findable when it comes up rather than only readable end to end. Search covers ids, body text and tags. (Seven of them are Echo Knight; nobody wants to scroll past those to reach the spells.)
- **Rulings that touch what your character actually has float to the top.** Tags are matched against your classes, subclasses, spells, feats, items and race — so an Echo Knight carrying Guidance opens on the seven Echo rulings plus the Guidance one, and a Rogue with none of them sees no such section at all.

**Presets, and handing a ruleset to a table.** *Load Lampmann's House Rules* fills in a complete worked example — the ruleset this module was built against; the source document is `house-rules/lampmann.md`. **Export ruleset** writes the whole configuration to one file — bans, source exclusions, settings, casting limits, and which ruling set is in use — and **Import** loads one back, so a DM configures a table once and hands out the result instead of everyone retyping a ban list out of a chat message. The file records the ruleset *as it stands* rather than as a pointer to a preset, so a table that started from a preset and then changed six things exports what it actually plays with. The ruling prose isn't copied in — that ships with the sheet, so only the set's name travels, and a file naming a set you don't have still imports cleanly. A file written by an older build loads too: anything it predates falls back to today's default. Picking the wrong file (a character export, say) is refused with a reason and leaves your ruleset untouched.

## Resting
Full PHB'14 p186 automation, split across two places: **Hit Dice** live in the HP & Defenses module (spending one is always your own choice, in the moment); the **Short Rest** / **Long Rest** buttons (Features module) handle everything that isn't a choice.

**Hit Dice** — one pool per row in the Classes table, sized and typed from that class's level and Hit Die (a Fighter 5 / Wizard 3 has a d10 pool and a d6 pool, not one pool of 8). Each pool **counts down from its maximum**: 17 Hit Dice reads `17/17`, and drops to `16/17` once you roll one, the same direction as every other consumable pool. Click **roll** to spend one: it rolls that class's die + your CON modifier to the Event Log, heals you for the total (minimum of 0 — a bad roll can't cost HP, but the die is still spent), and clamps at Max HP. The **remaining** count next to each pool is an ordinary override box — edit it directly to correct a misclick or to set up a character mid-adventure — the same "always give an override" rule as everywhere else on the sheet. A fresh character with no classes yet just shows a hint instead of an empty box.

**Short Rest** — opens a dialog, because spending Hit Dice is a decision made *during* the rest and one die at a time: PHB p186 has you "decide to spend an additional Hit Die after each roll", so the dialog rolls them singly and shows your running HP between rolls rather than asking for a count up front. It lists the same pools as the HP module (they stay in sync — roll in either place and both update).

Each roll takes effect **immediately** — it's a real roll, already in the Event Log, so it heals you and spends the die there and then. **Finish Short Rest** is what applies the *rest itself*: clearing Temp HP (PHB p197: temporary hit points last only until they're depleted or you finish *a* rest, short or long — not just a long one) and recovering any [feature effect](#feature-effects-automatic-mechanics) whose `uses` spec recharges on a short rest (also covering anything that recharges on a long rest). Closing with **Cancel**, Esc, or a click outside leaves the rest unapplied, but any dice you already rolled stay spent — the dialog says so up front, since un-rolling a die isn't something the sheet will pretend to do.

**Long Rest** — applies straight away with no dialog (there's no per-die choice to make). Clears Temp HP, restores current HP to max, regains spent Hit Dice up to half your total (minimum 1 if you have any), clears every used spell slot, **reduces Exhaustion by one level** (PHB p186) and **clears the Death Saves tracker** (p197 — regaining hit points wipes it, and a long rest takes you to full), and recovers every feature effect that recharges on a long or short rest (including counting down a delayed recharge). If your character is at 0 HP or below when you click it, a confirmation explains that PHB p186 grants no benefit from a long rest without at least 1 HP at the start of it — declining leaves everything untouched, exactly as if the rest had given nothing.

*Two documented simplifications:* regaining Hit Dice for a multiclass character with more than one die size fills pools in Classes-table order (RAW doesn't say which pool you choose when dice of different sizes are mixed) — same "approximate for multiclass, documented" tradeoff the rest of the sheet already makes for total-level-driven values. And Pact Magic (Warlock) isn't modeled as a separate slot pool at all (see [Spellcasting](#modules) above), so there's nothing Warlock-specific for either rest button to do — ordinary spell slots reset on a long rest as normal.

Both rest buttons record what they did in the [Event Log](#event-log-and-the-dice-roller) — including a rest that restored nothing, so an accidental click is visible rather than silent.

## Spell library (5e.tools import)
**Zero-click setup:** download the [5e.tools source data](https://github.com/5etools-mirror-3/5etools-2014-src) (the whole repo, or just its `data/` folder) and drop that `data/` folder next to `character-sheet.html`, so `data/spells/index.json` exists at that relative path. Reload the page — the sheet fetches `data/spells/index.json`, then every spell file it lists (`spells-phb.json`, `spells-xge.json`, …), and merges them in automatically. **Use the 2014 data** — the mirror above is the 2014 ruleset; don't point it at a 2024-only clone, and any stray `spells-xphb.json` (2024 PHB) is simply ignored since it's not referenced by the 2014 index.
- The **reload from data/ folder** button re-runs the fetch (e.g. after you add more source files) without a full page reload.
- If auto-load can't find `data/`, or the page was opened via `file://` (browsers block local-file `fetch()`), a status message next to the count explains which — and the old manual **import files** picker below it still works as a fallback for one-off or homebrew files.
- The library is cached locally either way, so this only costs time on first load.

This panel is **collapsed by default** — click **+ Add Spell** in the Spellcasting module (below) to open it; it stays open until you click that again.

**Browsing:** Each filter category (Source, Class, Level, School, Damage, Save, Cast, Components, Misc) is a row of **tri-state buttons** — click a button to cycle **neutral → include (blue) → exclude (red)**.
- **Per category:** `All` (include all), `Clear` (neutral), `None` (exclude all), a **blue** combine-mode button (how the include buttons combine) and a **red** one (how the excludes combine) — each cycles `OR → AND → XOR` — and `Hide`.
- **Module bar:** `Combine as AND/OR` (how categories combine with each other), `Show All` / `Hide All`, `Reset`, and `Manage Defaults` (saves the current filters as the default that `Reset` restores).
- **Source** buttons show the full book name on hover. A plain **search** box filters by name.
- **Class** is populated from `data/spells/sources.json` (5e.tools' separate per-spell class-list file — not part of `spells-*.json` itself), auto-fetched alongside the spell files; also detected by filename in the manual import picker. Without it, this row shows no buttons.
- Results are shown in aligned columns (level, name, school, save/attack, damage, conc, ritual, source).
- Click a spell's **name** to expand its full **description** (and higher-level text); click again to collapse.
- Click **`+`** to add it to whichever class is selected in the **Add to class** dropdown above the search box (auto-set to your only spellcasting class; pick one yourself if you're multiclassed) — it appears in the Spellcasting module's Spells list under that class.

*Note: nothing from 5e.tools is bundled with the sheet; `data/` is gitignored — you supply it, it's parsed in your browser.*

**Spells list (in the Spellcasting module):** spells you've added render like the Features panel — grouped by class, click a spell's **name** to expand its description with clickable inline dice (click a die roll to roll it) and "spell attack" text (click to make that attack, same as the old to-hit roll). Leveled spells get a **prepared** checkbox (cantrips don't — they're always available); **x** removes a spell. Above each class's spells, a summary line shows **Cantrips**, and either **Known** (Bard/Ranger/Sorcerer/Warlock/Eldritch Knight/Arcane Trickster) or **Prepared** (and, for Wizards, **Spellbook** too) against that class's computed maximum — these are informational only and never stop you from adding more.

## Features (5e.tools import: race + class + feats)
Same zero-click setup as the equipment library:
1. With the same `data/` folder in place (see above), the sheet auto-fetches the 2014 `class-*.json` files (fighter, wizard, etc.) from `data/class/`, plus `data/races.json` and `data/feats.json`, on load — no picker needed. **Reload from data/ folder** re-runs the fetch; **import files** below it is the fallback for `file://` use, or homebrew class/race/feat files (auto-detected by content, so class/race/feat JSON can all be dropped into the same picker).
2. The panel reads your **Race** + **Subrace** fields and lists your racial traits, then reads your **Classes** table (class name, subclass, level) and lists every class feature and matching subclass feature you'd have at that level. Names match case-insensitively; it updates live as you edit any of those fields.
3. Click a feature's **name** to expand its description; click again to collapse.
4. For any feature literally named **Ability Score Improvement**, you get the actual choice the rule offers: a **Feat** box, *or* two **+1 to…** pickers beside it. Picking the same ability in both is the +2; picking two different ones is +1 each — which is exactly how the rule reads, so neither shape needs a special case. It's one or the other, so choosing a feat greys the pickers out (clear the feat box to get them back, with your pick intact). What you take shows in the score's own audit tooltip alongside its base, your Misc terms and any feature bonuses. A **Feat** dropdown also appears next to it (populated from `feats.json`) — pick one and its description shows in place of the ASI's own boilerplate when you expand that feature. Your picks are saved as part of your character (export/import), not just cached locally like the rest of the library.
5. **Limited uses:** where a feature's [feature-effects](#feature-effects-automatic-mechanics) database entry declares a `uses` spec (max — e.g. proficiency bonus, an ability modifier with a minimum, or a fixed number — plus a short/long-rest recharge, or the delayed "roll 1d4 long rests to recharge" pattern), a row of **●/○** pips appears next to the feature showing uses remaining out of the computed max (proficiency bonus and ability modifiers are read live from your sheet). Click a pip to mark/unmark uses. **Short Rest** / **Long Rest** buttons in this module recover everything that recharges on that rest type (Short Rest also covers anything that recharges on a Long Rest); the delayed recharge is only rolled and counted down by **Long Rest** — and the same two buttons also drive the rest of a rest's mechanics (HP, Hit Dice, spell slots, Temp HP), covered in full under [Resting](#resting). Like the rest of the effects database, this is declared per-feature and inert unless your own imported `data/` contains a feature by that name — nothing is guessed from feature text at render time; a feature only gets a tracker once its `uses` spec has been written into the database (see [where game data comes from](#where-game-data-comes-from)).

**`data/backgrounds.json`** is loaded here too, for the [character creator](#characters-tabs-creation-levelling-up)'s background step. It isn't used anywhere else yet, so the sheet is entirely happy without it — the auto-load status line just says `no backgrounds.json`.

The library itself (class/race/feat data) is cached locally, separate from your character; use counts are saved as part of your character, same as feat picks. *Subraces that use 5e.tools' internal `_copy` inheritance (mostly non-PHB reprints/variants) aren't resolved and are skipped — direct-entry subraces (the PHB ones: High Elf, Drow, Hill Dwarf, etc.) work fine. Optional/choice class features that live in their own files — Fighting Styles, Battle Master maneuvers, Warlock invocations, Metamagic, etc. — aren't imported yet.*

## Feature effects (automatic mechanics)
Some features do more than describe themselves — they change a number elsewhere on the sheet. War Wizard's Tactical Wit adds your INT modifier to initiative; Alert adds a flat +5; Tough adds 2×level to max HP. Where the sheet recognizes a feature this way, it applies the effect automatically instead of asking you to type it into a Misc box.

**How it works:** a small, hand-authored, committed database (`effects/effects-db.js` + `effects/db/*.js`) maps a feature's name and origin (e.g. `feat|alert`, `subclass|wizard|war magic|tactical wit`) to a short declarative description of its mechanics — a target (`init`, `save-con`, `hpmax`, a skill, spell DC/attack, proficiency bonus, an ability score, …), an operation (add a flat bonus, add dice, grant proficiency/expertise, force advantage/disadvantage, …), and sometimes a value expression (an ability modifier, proficiency bonus, character/class level) or a choice (which ability Resilient boosts, which skill a feature picks). See [where game data comes from](#where-game-data-comes-from) for why this database is committed while the feature *text* it describes is not: the entries contain no sourcebook prose, and are inert unless your own imported `data/` actually contains a feature by that name — the file ships mechanics as an overlay, never content.

- **Always-on effects** (Tactical Wit, Alert, Tough) just apply — no interaction needed.
- **Toggleable effects** (things you turn on/off in play) show a small button both inline next to the feature in the Features panel and in the **always-visible effects strip** just under the toolbar, so you don't have to go hunting for it mid-combat. Click either one to flip it; both stay in sync.
- **Choice-driven effects** (Resilient's chosen ability, Observant's +1 ability) show a dropdown next to the feature; the effect only applies once you've picked.
- **Auditability:** any number the engine touched gets a dotted underline — hover it (or an ability score's small `= 17` note) to see exactly which features contributed what, e.g. `+7 = +2 DEX, +5 Alert`, or `16 base +1 (Observant) = 17`. Roll-log entries are annotated the same way (`[Alert +5]`). If you've also typed something into that stat's own Misc field, the tooltip warns you to check for double-counting rather than silently stacking.
- **Weapon effects reach the Attacks module.** `attack-hit`, `damage-bonus`, `damage-crit`, `attack-crit-range` and `attack-ability` are live: they fold into every attack row's to-hit, damage, crit threshold and ability (see [Attacks](#modules) for the per-row **Fx** opt-out). This is what the reserved-target scheme was for — Sharpshooter and Great Weapon Master were written against those names long before the module existed and switched on without being re-converted, and the crit targets did the same later. Any *other* `attack-`/`damage-`-prefixed name is still reserved the same way: valid to write today, applied the day something reads it. A toggle whose only targets are still reserved renders but stays disabled, labeled "serialized; nothing on the sheet reads this target yet".
- **Not everything is automatable yet.** Anything the engine genuinely can't represent (Lucky's reroll, anything needing a roll-history model) shows a plain `⚠ not automated` marker with the reason on hover. The effects strip's coverage counter (e.g. "3 feature effect(s) not automated") totals that plus anything still sitting on a reserved target, so gaps are visible, never silent.
- Coverage today: a handful of hand-written entries proving the schema (`effects/db/handwritten.js`), a full pass over the 2014 feats (`effects/db/feats.js`), **every 2014 race/subrace trait** (`effects/db/races-batch-01.js`–`08.js`), and **every class** (`effects/db/classes-batch-*.js` — artificer, barbarian, bard, cleric, druid, fighter, monk, paladin, ranger, rogue, sorcerer, warlock, wizard and the sidekick classes). All of it is wired into `character-sheet.html` and live. Race traits were extracted by `effects/tools/extract-race-features.js` and class features by `effects/tools/extract-class-features.js` (both mirror the live app's key derivation and text flattening); everything is merged only after passing `effects/tools/validate-db.js`. See `effects/tools/conversion-guide.md` for the schema/process used. Nothing in it talks to your character or your `data/` folder without you explicitly running it.
- **The schema, in one place.** A `when` block gates an effect on `minLevel`/`maxLevel`, `minClassLevel`/`maxClassLevel` (with `class: "@self"` for the feature's own class), `hasClass`, `casting`, and equipment state — `armor` (an allow-list of categories you may be wearing), `notArmor` (the deny-list form the rules phrase themselves in, as in Fast Movement's "while you aren't wearing heavy armor"), and `shield`. Armour state is read from what's actually equipped, through the same lookup the AC formula uses, so a predicate and the AC it implies can't disagree; a shield is deliberately not body armour. An **unrecognized predicate leaves the effect inactive** rather than applying it — degrade to manual, never guess.

  Value expressions are literals or `{mod}`, `{prof}`, `{level}`, `{choice}`, `{sum}`, `{mul}`, `{floor}`, `{ceil}`, `{round}`, `{div}`, `{max}`, `{min}`. Ops are `add`, `adddice`, `min`, `max`, `set`, `prof`, `expertise`, `adv`, `dis`, `note`, plus four that cover what used to be unexpressible: **`diefloor`** ("treat a d20 of 9 or lower as a 10" — routed through the roller's own `mi` operator so the floor shows in the rolled dice rather than quietly adjusting a total; target `check-proficient` for the Reliable Talent form, or a named skill), **`critrange`** (a widened crit threshold; the lowest wins), **`useability`** (*replace* the ability a roll uses rather than adding to it), and **`tag`** (a standing fact rather than a number — `resist-<type>`, `immune-<type>`, `vuln-<type>`, `save-vs-<condition>`, `situational-advantage` / `situational-disadvantage`, all listed under HP & Defenses). `adddice` takes a literal or a computed `{ count: <value expr>, die: "d6" }`, which is how Sneak Attack is written once as `ceil(rogue level / 2)d6`; a computed count of zero contributes no term rather than a bogus `0d6`. Separate movement speeds go on `speed-fly` / `speed-swim` / `speed-climb` rather than adding to walking `speed` — as a number where the rules give one, or as a `tag` where they don't ("equal to your walking speed", "+10 ft, if you have one"), since a value expression deliberately can't read another target.

- **What "converted" means.** A lot of features are *recognized but not applied*, and that's the honest state rather than a gap in the conversion — a feature the engine can't represent shows `⚠ not automated` with the reason on hover, and the effects strip counts them so gaps are visible rather than silent. Some are recognized and *listed* rather than applied, which is a deliberate third state: **situational advantage and disadvantage** ("on Stealth checks in rocky terrain", "on attack rolls in direct sunlight") appear on a Situational line under HP & Defenses, credited to the feature that grants them, because the trigger is terrain, lighting, or what some other creature is doing — none of which the sheet can see. Applying them unconditionally would be wrong far more often than right. What's genuinely left, now that level-banded dice, crit ranges, per-die floors, ability swaps, speeds, resistances and condition saves all have homes: **action economy** (Extra Attack, Polearm Master, War Priest — extra attacks are not a number on a roll), **AC**, which still isn't an effects target, **temporary hit points**, which have no model, **optional-feature files** (Fighting Styles, Metamagic, Eldritch Invocations), which the sheet doesn't import yet, and anything needing **per-weapon context** — "heavy weapons only", or a crit die the weapon itself defines (Savage Attacks, Brutal Critical), since the attack buckets are global and every row reads the same ones. Features that only change *another creature's* numbers (Cutting Words, Unsettling Words) are omitted outright rather than marked, since nothing on your sheet would move either way.
- Features not covered by a full conversion still get their **limited-use pip trackers** from `effects/db/uses-classes.js` and `uses-races.js` — a `uses`-only stopgap produced by the deterministic scanner `effects/tools/generate-uses.js`, which recognizes explicit finite-use + recharge phrasing and deliberately skips features whose use-count itself scales by level (Action Surge, Channel Divinity) rather than committing a flat number that would be wrong at most levels. When a feature gets a full conversion pass, its key moves out of that file and into the batch: `registerEffects()` assigns whole entries rather than merging fields, so a key defined in both places would erase one side or the other rather than combine them. `generate-uses.js` skips already-converted keys automatically, and `validate-db.js` fails on any duplicate that slips through.

Same zero-click setup as the spell library:

2. **Reload from data/ folder** re-runs the fetch; the **import files** picker below it is the fallback for `file://` use or homebrew item files.
3. The library is cached locally, so this only costs time once.

**Browsing:** a **search** box matches name, type, rarity, and source all at once — type "potion", "rare", or "phb" and it filters. Results show name, type, rarity, weight (lb), and value (gp, converted from 5e.tools' copper-piece figure). Click **`+`** to add a row straight into your Inventory table (qty 1, weight and value pre-filled) — from there it's counted in the item-value and total-wealth sums automatically.

**Filters:** the same tri-state button system as the [Spell library](#spell-library-5etools-import) — click a button to cycle **neutral → include (blue) → exclude (red)**, with per-category `All`/`Clear`/`None`, blue and red combine-mode buttons (`OR → AND → XOR`) and `Hide`, plus the module bar's `Combine as AND/OR`, `Show All`/`Hide All`, `Reset` and `Manage Defaults`. | Category | Notes |
|---|---|
| Source, Type, Property, Weapon Damage Dice, Bonus, Miscellaneous, Found On | populated from whatever you actually loaded, so they shrink to fit your `data/` |
| Tier, Rarity, Category | Category is Basic / Generic Variant / Specific Variant / Other — how 5e.tools separates a plain longsword from the generic "+1 Weapon" template from the specific "+1 Longsword" |

| Spellcasting Focus | listed by class rather than by the raw arcane/druid/holy code the data stores |
| Weapon Damage Type | the weapon's own damage type |
| Vulnerability, Resistance, Immunity | three separate categories rather than 5e.tools' one nested "Damage" group |
| Condition Immunity, Recharge Type, Poison Type | |

**Bonus** offers both a bare form and a valued one — `Weapon Attack and Damage Rolls` matches any `+N` weapon, `Weapon Attack and Damage Rolls (+2)` only the `+2`s.

*Not yet implemented:* the four **range** facets 5e.tools also offers (Cost, Weight, Armor Class, Range) need a slider rather than tri-state buttons, and the free-text ones over huge value sets (Base Item, Attached Spells) are left to the search box.

**Default magic item prices:** individual magic items rarely carry an explicit price in the source data — when one doesn't, the sheet fills in the average of XGE's "Magic Item Price" table (Xanathar's Guide to Everything, p.126) instead of leaving it blank: **common 45gp · uncommon 350gp · rare 11,000gp · very rare 35,000gp · legendary 175,000gp** (halved for single-use consumables, per that table's own footnote, when the item's data marks it as one). Artifact/varies/unknown-rarity items are left blank rather than guessed — that table doesn't cover them. Defaulted values show with a `~` prefix in the results table so they're never confused for an item's actual listed price.

*Note: nothing from 5e.tools is bundled with the sheet; `data/` is gitignored — you supply it, it's parsed in your browser.*

## Companions & summons (bestiary import)
Statblocks you actually play with — familiars, steeds, wild shapes, animal companions, mounts, and above all **summons**. Built around the way summons are used in practice: they arrive eight at a time, and they belong to the player casting them, not to whoever is running monsters. There is no GM-only gate on any of it.

**Bestiary Library** — the same import/search/filter panel as the [Spell](#spell-library-5etools-import) and [Equipment](#equipment-library-5etools-import) libraries, over `data/bestiary/`. Two things work differently, both forced by the data:

- **It loads lazily and isn't cached.** The bestiary is ~9 MB across ~96 files — an order of magnitude more than the spell (1 MB) or equipment (2 MB) libraries. Rather than pay that on every page load for a panel many characters never open, it loads on first need: when you open the library, or automatically on load if your character already has companions whose statblocks have to resolve. That's about a second from a local server. It's also the one library not cached to `localStorage`: the parsed bestiary is ~14 MB, more than every other cache combined, and keeping it would spend most of the origin's storage budget — and risk evicting the spell and item caches, which are read far more often — to save that one second.
- **`_copy` entries are resolved.** About 30% of 5e.tools' monsters are stored as a diff against another monster ("Acidic Mist Apparition" *is* an Air Elemental with some text swapped and its immunities changed), often against a base in a different file — so every raw entry is indexed before anything is parsed. The `_mod` operations that the 2014 bestiary actually uses are applied (`replaceTxt`, `replaceArr`, `append`/`prepend`/`insert`/`removeArr`, `setProp`, `addSkills`). Two aren't: 5e.tools' **creature templates** (`_templates`) and its **spell-list edits** (`replaceSpells`/`addSpells`/`removeSpells`). Those entries still resolve to a correct base statblock; they're marked with a `*` in the results list and carry a warning at the top of the expanded block, rather than quietly presenting a partial statblock as complete. *(This is a deliberate contrast with the class/race library, where `_copy` subraces are skipped outright — skipping 30% of the bestiary, including a lot of published summon and NPC variants, wasn't an option.)*

Filters mirror 5e.tools' own bestiary panel — Source, Source Group, Type, Size, Movement, Senses, Environment, Summoned By, Damage Dealt, Resistance/Immunity/Vulnerability, Condition Immunity, Traits, Actions, Misc — plus five numeric-range facets (**CR, AC, HP, Walk Speed, Fly Speed**) using the same `kind: "range"` control the Equipment Library's Cost/Weight filters use. That combination is the point: *beast · CR ≤ 2 · has a fly speed* is the Conjure Animals shopping list, and it answers in one click. A creature with no value for a numeric facet (a summon spirit has no CR at all) fails an active bound rather than being silently swept in as a 0.

**Your creatures** — click **+ Add Creature** to open the library, then `+` on any row. Like items and spells, a companion stores only what's yours to change (how many, current HP, what level you cast the summon at); the statblock itself is looked up live by name, never copied and hand-edited.

- **A companion is a stack, not one creature.** Set the count and each one tracks its own HP — one entry, eight wolves, eight HP boxes, with a running `7/8 up`. HP boxes are [math fields](#number-boxes-math-input): type `-7` to take 7 damage, `+3` to heal. A creature at 0 is dimmed and struck through but stays on the sheet, since "how many are left" is the number you're actually tracking.
- **`×N all` rolls the whole stack.** Every attack on a multi-creature stack gets one, rolling that attack once per living creature and emitting a single log entry: a **damage-by-AC-range table** up top with the individual swings collapsed below — the same summary (and the same `acRangeRows`) that [Offensive Routines](#modules) produces for your own turn. Crits auto-double their damage dice. Shift = advantage on every swing, Ctrl = disadvantage. Eight wolves become one decision instead of eight lines of arithmetic.
- **Everything is a roll button.** Each attack gets to-hit and damage; every companion gets initiative, all six saving throws (a monster can attempt any save — the ones it's listed for just have a better bonus than raw ability), and any skill its statblock lists. To-hit/save/skill/initiative buttons go through the shared dice engine (`.mon-roll` is registered in `D20SEL`), so Shift/Ctrl advantage, the right-click Normal/Advantage/Disadvantage menu and the modifier tooltip all work exactly as they do on your own stats.
- **Click the name for the full statblock**, rendered in 5e.tools' own layout with every `{@damage}`/`{@dice}`/`{@hit}` click-to-roll, reusing the Spellcasting module's inline renderer.

**Scaling summons read your sheet.** Tasha's-style summons (Summon Beast, Summon Fey, …) ship their statblock with placeholders instead of numbers — `{@hitYourSpellAttack}` for the to-hit, and `summonSpellLevel`/`PB` inside damage expressions. Those are parsed through unresolved and substituted at roll time from your own **spell attack bonus**, **proficiency bonus**, and the **cast at level** box on that companion, so a Bestial Spirit's Maul is genuinely `1d8 + 4 + <the level you cast it at>` and its to-hit tracks your casting stat rather than a number frozen at 2nd level. Their `your spell save DC` text is likewise annotated with your actual DC. Their **HP can't be computed** — the source gives prose ("20 or 30 + 5 for each spell level above 2nd"), not a formula — so a fresh summon's HP starts *unknown* rather than 0 (it counts as up, not dead), and the **max** box next to it is the usual override: type the number once and every token fills in.

*Known limits:* an attack's damage button sums every damage die in the action, so a Giant Spider's Bite reads `1d8 + 3 + 2d8` even though the poison half is save-for-half — the same simplification the [Attacks](#modules) module already makes for your own weapons. Multiattack, recharge timing, and legendary/lair action economy are shown as text, not tracked or enforced. Companions don't interact with the [feature effects](#feature-effects-automatic-mechanics) engine at all: nothing on your sheet modifies a companion's numbers, and nothing a companion does feeds back into yours.

*Note: nothing from 5e.tools is bundled with the sheet; `data/` is gitignored — you supply it, it's parsed in your browser.*

## Interaction feedback
Every button, filter chip, tab and clickable name answers the same two questions: *is this clickable?* and *did my click land?* Hovering tints the control; pressing it darkens it further and nudges it down a pixel, so a click reads as distinct from a hover rather than as a flash. Clickable text underlines and brightens on hover. Disabled controls opt out of all of it and take a `not-allowed` cursor, so a greyed-out **Next** reads as refusing the click rather than as a dead button. Keyboard focus draws a ring (`:focus-visible`, so mouse clicks don't leave one behind).

It's one block in [css/base.css](css/base.css) covering every kind of button at once rather than per-component rules, and the colours are theme variables (`--hover-bg`, `--active-bg`, `--focus-ring`) that each of the eight themes retunes — a dark theme needs a lighter hover than a light one.

## Theme
The **Theme** dropdown in the toolbar swaps the sheet's look via `css/themes/*.css` (each just redefines the CSS custom properties set on `:root` in `css/base.css` — colors, borders, fonts). Ships with 12 alternates alongside the plain **Default (unstyled)** look; your choice is remembered (localStorage) across reloads. Drop your own `css/themes/your-theme.css` and add it to `css/themes/index.json` to add more.

- **Dark Mode** — the default look, inverted for low light. Same serif body font and sharp corners as Default, no gradients or glow; for anyone who just wants the lights off rather than a full re-skin.
- Five pairs, each an original plus a more ornate pass over the same palette — gradient-bordered module cards, gradient-text headers, a themed dice-log scrollbar, filter pills, tooltips/menus — the same "original, then polished" relationship Blood Moon Gothic has to Crimson Eclipse:
  - **Illuminated Manuscript** / **Gilded Folio** — aged vellum and gold leaf.
  - **Cyber Grimoire** / **Neon Codex** — black-and-neon cyberpunk, the polished pass adding scanlines and a glitch-flicker header.
  - **Blood Moon Gothic** / **Crimson Eclipse** — crimson horror.
  - **Verdant Feywild** / **Wildwood Court** — a soft fey forest, the polished pass adding dappled light and firefly accents.
  - **Infernal Bronze** / **Molten Covenant** — forged demonic metal, the polished pass adding a forge-glow backdrop and a pulsing ember header.
- **Celestial Aurora**, **Deep Sea Leviathan** — ornate from the start; no separate polished pass.

All the ornate themes are CSS-only (gradients, shadows, `background-clip: text`) — no external images or fonts, so they still work fully offline.

## Layout (move / resize / snap)
By default modules flow down the page. The **Layout** bar (above the modules) turns on free-form arranging:
- **Free (move/resize)** — EDIT mode. Modules become freely positioned; **drag anywhere on a module** to move it, and **drag any edge or corner** (8 handles) to resize. While editing, the modules' inputs are disabled and text-selection is off (so dragging never fights the controls), and — when snap-to-grid is on — a grey grid is overlaid. The arrangement is **kept when you turn Free off**; leaving edit mode just re-enables the inputs, it doesn't revert your layout.
- **Snap to grid** — positions and sizes (drag **and** resize) snap to a grid; the **grid** box sets the cell size in px. When editing with snap-to-grid on, a grey grid is overlaid.
- **Snap to modules** — while dragging or resizing, edges snap to align with (or sit flush against) other modules' edges.
- **Multi-select** — drag a box across empty space to marquee-select modules (Shift-click to add/remove one; Esc clears). Then **drag any selected module to move them all together**, or drag the selection box's handles to **resize them all at once**. A module you move jumps to the **front and stays there**.
- While dragging, the page **auto-scrolls** when you near an edge (faster the closer you get), and modules track the scroll so they never lag behind.
- **reset** returns to the default flow (and expands anything collapsed); **save file** / **load** export and import the arrangement as a JSON file.

When a module is smaller than its content (after resizing), it **scrolls** — mouse wheel, scrollbars on both axes, and native middle-click autoscroll — as long as you're **not** in Free mode. (While Free is on, overflow is clipped instead, so the resize handles stay pinned to the module's edges rather than scrolling away.)

Your arrangement is also saved locally (separate from the character; per browser). Styles live in [css/layout.css](css/layout.css) (theme-aware) and the logic in [layout.js](src/layout.js) — a self-contained module that works on any `.module`, so new modules are automatically arrangeable.

### Collapsing modules
Click the **▾** next to any module's title to collapse it down to just that title bar; click the **▸** to bring it back. Collapsed state is remembered the same way the arrangement is (localStorage, part of the same layout file), so it survives a reload and travels with **save file** / **load**.

What "collapse" does about the space it frees up depends on whether you've ever turned Free on:
- **You haven't** (the common case — modules just flowing down the page): nothing extra is needed. Collapsing a module removes its height like any other CSS change, and the plain page flow closes the gap by itself.
- **You have** (modules are freely positioned): collapsing one leaves a hole where it was, and the hole stays. Nothing else moves. An arrangement you built by hand rearranging itself because you folded something is exactly the "helpful" surprise this sheet avoids elsewhere — the space is yours to use or close.

The collapse toggle stays clickable **while Free is on**: folding a module is part of arranging the sheet, not part of using it, and it was the one control you had to leave Free mode to reach. Everything else inside a module stays inert while arranging, so a drag across a checkbox moves the module rather than ticking the box.

A folded module remembers **its own height, separately from its open one**. Drag its bottom edge while folded and it stays that tall when folded; unfolding restores the height it had open, so a folded module dragged short can't clip the content waiting behind it.

*(Known rough edge: a module's text can reflow oddly mid-resize — to be smoothed once the modules are finalized.)*

## Saving & loading
- **Autosave** to the browser (localStorage) on every change, into the **active character's** slot in the roster (see [Characters](#characters-tabs-creation-levelling-up)). The save indicator reports what actually happened: if the write fails — localStorage quota, which a large roster with long Event Logs can reach — it says **NOT SAVED** in red rather than claiming success, because at that point the character exists only in memory and closing the tab loses it. Export it to a file, then free space by deleting characters you no longer need or clearing old logs.
- **Export JSON** downloads the character you're looking at. **Import** loads one back into it. **Reset** blanks it — the character you're looking at, back to an empty sheet; your other tabs and the pre-roster backup (`charsheet-v0`) are untouched. All three work on a single character, not the whole roster.
- The spell library and equipment library are stored separately from your character (and are shared by all of them).

## Keyboard
- **Enter** in a number box commits the math and moves on.
- **Enter** on a focused checkbox toggles it.
- **Enter** in the dice box runs the command.

## Tests
Browser harnesses under `tests/` — open one through the local server (e.g. `http://localhost:8931/tests/derived.html`) and it prints `N passed, M failed`. No build step and no test framework: each file is a minimal copy of `character-sheet.html`'s DOM with the real `src/*.js` loaded on top, so what runs is the app's own code rather than a reimplementation of it.

- **[tests/derived.html](tests/derived.html)** — the pure math: proficiency bonus, max HP (including the first-class-only maximum at level 1 and negative CON), the multiclass caster-level and slot table (Pact Magic excluded), known/prepared/cantrip allowances, unarmored AC, save/skill totals with proficiency and expertise, `parseBonus`'s flat/dice split, and the number boxes' arithmetic and clamping.
- **[tests/effects.html](tests/effects.html)** — the feature-effects engine and the roster/grouping logic.
- **[tests/filters.html](tests/filters.html)** — the shared filter engine behind the Spell and Equipment libraries.

The effects file loads the real effects database; the other two are self-contained and need no `data/` folder.

## Roadmap / known limits
Only what is still outstanding. Anything finished has been removed from this list and is described in
its own section above; the [Tests](#tests) suite is the record of what actually works.

**Known limits of what shipped**
- Icon variants for modules and the toolbar — not built.
- Spell damage shown or rolled from an expanded spell description is base dice only; there's no upcast math beyond what 5e.tools' own scaling data already resolves for cantrips.
- The character creator reports rather than resolves an equipment line the data states as a filter ("any martial weapon"), and names rather than grants magic items from the DMG p38 table (there's no random magic-item table on the sheet).
- **Death Saves has no rules-reference button.** The other trackers get a **ⓘ** expanding the official text, but death saving throws are core PHB prose rather than a named condition, so 5e.tools' `conditionsdiseases.json` has no entry to show.
- **Resistances, immunities and vulnerabilities** can be granted by a feature or typed in by hand, but nothing applies them to incoming damage — the sheet doesn't model damage taken.
- The Combat round tracker has a local initiative order (see [Combat rounds](#combat-rounds)) but no legendary/lair actions and no link to limited-use features — spending a Bonus Action on Second Wind doesn't tick its pip.
- Death saves are tracked but not applied to anything else. Conditions and exhaustion now *are* applied — see [Conditions and exhaustion](#conditions-and-exhaustion) — except for the three kinds of effect listed there, which are shown rather than applied on purpose.
- Companions & summons have no save-for-half damage splitting, no action-economy tracking (Multiattack, recharge, legendary), and no interaction with the feature-effects engine.

**Feature effects**
- Still to convert: ~80 keys that carry a `uses` pip tracker and nothing else (about 23 racial, the rest spread across every class, clustering in ranger, paladin and warlock). Most are pure limited-use abilities with no standing number to hold — Healing Hands, Breath Weapon, Elder Champion — and the tracker is the whole of what a sheet can do for them. A minority genuinely are a backlog: Elemental Gift and Form of Dread have real numbers behind a toggle. Everything else — all 2014 feats, all races/subraces, all twelve classes plus the sidekicks — is done (`effects/db/*.js`).
- **The one engine gap left is per-weapon context.** Effects are a single global bucket that every attack row reads, so nothing can say "heavy weapons only", or "one more of *this weapon's* damage dice" (Savage Attacks, Brutal Critical) even though `damage-crit` now exists. Each row's **fx** checkbox is the manual stand-in. Fixing it means evaluating effects per row rather than once per character — an architecture change rather than a schema addition.

**Planned**
- **A statblock as its own character, with an origin.** The [Companions & Summons](#companions--summons-bestiary-import) module covers statblocks you *own*, which is the common case. What it doesn't do is make one a character in its own right — its own tab, its own sheet — which is what you want for a familiar you play as much as your wizard, and which would pair with [character groups](#characters-tabs-creation-levelling-up) (a summoner and their summons in one group already share an Event Log; that's most of why grouping exists). The other half is the **origin**: pick Bat as the statblock and *Find Familiar* as the origin, and the spell's own constraints apply to that sheet — a familiar "can't attack", so the Attacks module should say so rather than offering the roll. That's the same job the [feature-effects engine](#feature-effects-automatic-mechanics) already does for a character, pointed at a statblock instead.
- More of the books' **optional rules wired to real numbers**. All 116 are catalogued and switchable ([Optional rules](#house-rules-bans-sources-campaign-settings)); four change your numbers today. Most of the rest are DM-facing procedure a character sheet has nothing to compute for, but a few (Spell Points, Skill Variants, Hero Points' death-save spend) could go further.

**Not planned**
- Personality traits, ideals, bonds, flaws, backstory, and appearance fields (age/height/eyes/etc.). This sheet targets optimized play, not roleplay journaling — that content belongs in a separate document.
- A numeric **Duration** filter for spells. 5e.tools' raw duration amounts mix incompatible units (rounds/minutes/hours/days) with no common numeric axis to slide across, so it stays categorical.

## Eventual goal: self-hosted multiplayer VTT + AI table companion
Two long-range, unscheduled goals, in the order they'd have to happen (the second depends on the first). Estimates are **person-hours of traditional human dev time**, broken into constituent parts, assuming the "Foundry model": one player runs a small self-hosted server (extending the existing `pmcrwf` local-server launcher) that holds authoritative session state and pushes updates to everyone's browser over WebSockets — not a hosted service, not peer-to-peer.

These estimates assume this table's actual house rules, not generic-VTT defaults — which changes scope meaningfully versus a Foundry/Roll20-style build:
- **Total informational transparency.** Metagaming and reading the module are allowed; no fudging, no hidden rolls, no hidden info. This means **fog of war, vision/line-of-sight, and whisper/hidden-roll tooling are out of scope entirely** — a whole category of VTT complexity (and cost) just doesn't exist here.
- **The GM has zero special permissions.** They run the monsters and that's it — no rules-arbitration authority, no GM-only UI, no hidden-info gate to build. The data model and session UI are flat: any player can act on any actor, not tiered by role.
- **Everyone needs monster-statblock access, not just the GM** — summons (Conjure Animals, Find Familiar, wild shape, etc.) are used constantly, so the statblock/monster library has to be a shared, player-facing resource from day one, not a GM tool.

*(In practice, AI-assisted dev — especially with subagent parallelization — tends to compress pure code-writing well below these numbers; the parts that don't compress as much are the ones bound by human judgment/testing rather than typing: decision-quality tuning and multiplayer edge-case hardening. Treat the totals below as the human-equivalent baseline, not a wall-clock prediction.)*
